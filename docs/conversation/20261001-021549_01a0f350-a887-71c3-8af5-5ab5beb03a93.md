**① 配信単位の状態処理と、永続化・DB反映を分離する**

コメント・リアクション・NG登録・通報・入退室を、配信単位で順序を守って処理します。判定と応答に必要な状態はメモリに置き、変更をローカルの永続ログへ追記します。複数配信のログをまとめて同期保存し、その完了後に成功応答を返します。MySQLへの反映は別の処理でまとめます。

これにより、投稿の応答経路からBEGIN、参照SQL、INSERT、SAVEPOINT、COMMITの連続した往復を取り除けます。別配信のNG登録や通報による待ちも分離できます。

## ASSISTANT (Worked for 28s)

**ロック収集側の接続先設定漏れです。**

[collector設定](/Users/mineo/src/github.com/EkeMinusYou/isucon13-03/tools/measurectl/collectors.yaml:149)の`mysql-locks`には`-dsn`がなく、既定の`127.0.0.1:3306`へ接続していました。一方、MySQLは`172.31.37.38`で待ち受ける設定なので、接続が拒否されています。

RUNに記録されたエラーは次のとおりです。

```text
dial tcp 127.0.0.1:3306: connect: connection refused
```

通常のMySQL status収集はUnix socketを明示しているため成功しています。ロック収集にも同じ設定を追加すれば、この接続先の不一致を解消できます。

```text
-dsn 'root@unix(/var/run/mysqld/mysqld.sock)/'
```

ロックTSVの`captured_waits=0`は収集エラーを伴っており、「ロック待ちがなかった」という意味ではありません。設定はまだ変更していません。
